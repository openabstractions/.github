# Layer catalogue

Generated by scripts/catalogue.py from the layer definitions, scripts/split.manifest, docs/results/MATRIX.txt and docs/platforms.json. Edit those inputs and regenerate; scripts/catalogue.py --check refuses a stale copy.

Measured on 2026-09-28. Each language row gives the verdict of the legacy whole-layer grid for the layer's own implementation (— is none), then the client: the facade's resolve accessors, or for JavaScript the generated service clients a binding from Machine.resolveService wraps. UNPROVEN means the grid found nothing to check: usually source for that layer and language exists with no test files the gate names, so no run happened and no verdict, pass or fail, was recorded. For an adopter, an UNPROVEN cell means the binding compiles and its behaviour is unverified on that platform; ship on a PASS cell.

**Contracts:** `abstraction.storage/content-reader@1 (resolved by the facade)`, `abstraction.storage/content-writer@1 (resolved by the facade)`, `abstraction.storage/content-changes@1 (resolved by the facade)`, `abstraction.storage/holds@1`, `abstraction.storage/manifests@1`, `abstraction.storage/inventory@1 (resolved by the facade)`, `abstraction.storage/content-remover@1`, `abstraction.storage/inventory-source@1`, `abstraction.storage/lend@1 (resolved by the facade)`, `abstraction.storage/store@1 (direct interface)`, `abstraction.storage/local@1 (direct interface)`, `abstraction.storage/writable@1 (direct interface)`.

| Language | Matrix and client |
| --- | --- |
| Go | matrix UNPROVEN; client ResolveLending, ResolveStorage, ResolveStorageChanges, ResolveStorageInventory, ResolveStorageWriter |
| Python | matrix UNPROVEN; client resolve_storage, resolve_storage_changes, resolve_storage_writer |
| C++ | matrix UNPROVEN; client resolve_storage, resolve_storage_changes, resolve_storage_writer |
| Rust | matrix UNPROVEN; client resolve_storage, resolve_storage_changes, resolve_storage_writer |
| JavaScript | matrix UNPROVEN; client ContentChangesClient (abstraction.storage/content-changes@1), ContentReaderClient (abstraction.storage/content-reader@1), ContentRemoverClient (abstraction.storage/content-remover@1), ContentWriterClient (abstraction.storage/content-writer@1), HoldsClient (abstraction.storage/holds@1), InventoryClient (abstraction.storage/inventory@1), InventorySourceClient (abstraction.storage/inventory-source@1), ManifestsClient (abstraction.storage/manifests@1) |

**Platforms:** the runtime's (Runtime platforms above); supported: windows-user, windows-machine, linux-systemd-user; supported without background services: linux-no-user-manager; unsupported: macos, android-termux.

**Install:**

- repository github.com/openabstractions/abstraction-storage (published)
- Go: go get github.com/openabstractions/abstraction-storage/go
- Python: abstraction-storage-content, installed from source
- Rust: crate abstraction-storage-content-api, from source
- JavaScript: @openabstractions/storage-content, from source
- C++: CMake package from source (cpp/)
- runtime: the redist runtime installer: a Windows MSI, Linux tarballs and a macOS package
